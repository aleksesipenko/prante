# HEARTBEAT.md — фоновые проверки ПРАНТЕ

_ПРАНТЕ работает в Telegram-first режиме. Heartbeat — это короткие
фоновые проверки, которые не должны превращаться в шум. Держим файл
маленьким, чтобы не сжигать токены по пустякам._

## Режим по умолчанию

Если в файле нет активного чек-листа — отвечаем `HEARTBEAT_OK` и
ничего не делаем. Не превращаем heartbeat в генератор идей.

## Что ротировать (опционально)

Эти проверки имеет смысл включать, когда переводчик работает в
долгих сессиях и хочет, чтобы ПРАНТЕ сам подсвечивал полезное:

- **Новые сообщения в основном Telegram-диалоге** — если есть
  непрочитанные, кратко обозначить (не отвечать за переводчика).
- **Просроченные кандидаты в глоссарии** — если в plugin DB есть
  `candidate` старше 7 дней без активности, тихо напомнить
  переводчику («висит 3 термина-кандидата, подтвердить?»).
- **TM-контекст под текущий проект** — если в течение сессии текст
  менялся, пересчитать, нет ли новых fuzzy-матчей.

## Состояние проверок

Короткая память о последних heartbeat-чеках. Только локальная,
не синхронизируется с `MEMORY.md` / `USER.md`. В git не коммитим,
если в `.gitignore` не оговорено иное.

```json
{
  "lastChecks": {
    "telegram_unread": null,
    "glossary_candidates_stale": null,
    "tm_drift": null
  }
}
```

## Чего НЕ делать в heartbeat

- Не предлагать новые термины без детерминированной проверки.
- Не лезть в operator smoke режим и не писать в `MEMORY.md`.
- Не инициировать диалог с переводчиком без повода.
- Не запускать тяжёлые plugin-тулы (`prante_analyze_text` на
  большом корпусе) в фоне — это только по явной задаче.

## Когда выключать heartbeat полностью

Если переводчик в длинной фокус-сессии, в чате уже идёт активная
работа, или runtime под нагрузкой — heartbeat лучше держать
минимальным или пустым. Heartbeat существует, чтобы **помогать**,
а не перебивать.
