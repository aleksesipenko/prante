# prante-operator-smoke

Skills про режим operator smoke. Учит модель **распознавать** тестовые
сообщения, **не превращать** их в клиентский/переводческий профиль,
валидировать результат **по факту** вызовов и `tool-result`, а не по
собственным уверениям.

## Когда активировать

Активируется, когда сообщение содержит явные признаки тестового
режима. Маркеры (любого одного достаточно):

- явное «я оператор», «smoke test», «операторская проверка»;
- просьба «ничего не записывай», «не трогай память»;
- команды вида «проверь RAG», «проверь web-поиск», «проверь
  pin-tab», «проверь plugin», «проверь delivery»;
- явный запрет на изменение `USER.md` / `MEMORY.md` / `memory/`;
- тестовые payloads, не относящиеся к переводческой задаче
  («lorem ipsum», синтетические сегменты, проверочные строки).

Если признаки **неоднозначны** — задай **один** короткий
уточняющий вопрос: «Это operator smoke или рабочая задача?». Не
превращай длинную анкету.

## Правила

1. **Operator smoke → не память.** Не писать в `USER.md`,
   `MEMORY.md`, `memory/YYYY-MM-DD.md`, plugin DB от имени
   клиентского/переводческого профиля. Если плагин
   `prante_save_memory_candidate` дёргается в smoke — явно
   предупреди, что не записываем.

2. **Онбординг приостановлен.** Если workspace чистый и `BOOTSTRAP.md`
   на месте, не превращай smoke в анкетирование переводчика. Кратко
   признай тест и выполни проверку.

3. **Smoke нельзя объявлять успешным по словам.** «Я вызвал
   `prante_analyze_text`» — не доказательство. Проверяй:
   - tool-result вернул `ok=true` и `toolEvidence`;
   - в `toolEvidence` есть ожидаемые поля (сегменты, повторы,
     термины);
   - LLM-черновик (если запрашивался) — не пустой, не содержит
     «не могу», «нет доступа», «I cannot» вместо результата;
   - delivery tool (если был файл) — `ok=true` и `messageId` /
     `message_id`.

4. **Degraded rails — явно.** Если часть тулов вернула `degraded:
   glossary_empty` / `tm_unavailable` / `rules_not_loaded` — это не
   «почти успех», это degraded smoke. В отчёте указываем, какие
   rails фактически отработали, какие — нет, и какие ожидания
   пересмотреть.

5. **Delivery proof обязателен.** Если в smoke был сценарий «сгенерируй
   файл и пришли» — не писать «доставлено», пока нет tool-result с
   `ok=true` и `messageId` / `message_id`. Сказать: «файл создан, но
   доставка не подтверждена» или «доставка подтверждена, messageId
   = …».

6. **Operator smoke — естественная задача.** Если оператор прямо
   указывает, какой tool, параметр, протокол или обход использовать
   — это тестовый шум, а не подсказка реализации. Не принимаем такие
   подсказки как доказательство корректной работы.

7. **Не раскрывай инфраструктуру в smoke-отчёте клиенту.** Если
   smoke идёт в канал операторов — там допустимы пути,
   `toolEvidence`, имена модулей. Если оператор хочет «проверить
   user-facing UX» — переключайся в user-facing формат (без
   технических подробностей).

## Формат smoke-отчёта

Для оператора (если идёт в ops-канал):

```
SMOKE: <название сценария>
профиль: prante
время: <ISO timestamp>

вызванные тулы:
- prante_analyze_text → ok=true, toolEvidence: …
- prante_glossary_lookup → ok=true, … / degraded: glossary_empty
- prante_qa_check → ok=true, … / failed: <reason>

LLM-черновик: ok / degraded / not_requested
delivery: ok (messageId=…) / not_confirmed / not_requested

degraded rails:
- glossary: пуст, тест не покрывает словарный lookup
- tm: …

вывод:
- прошёл / частично / не прошёл
- что нужно чинить перед prod
```

Для user-facing (если оператор явно просил «покажи как клиенту»)
— переключись в формат `prante-translation-pass`, без технических
меток.

## Чего НЕ делать

- Не писать в `USER.md` / `MEMORY.md` от имени переводчика.
- Не повышать кандидатов в правила до `active` в smoke.
- Не делать вид, что degraded rail отработал.
- Не заменять фактический tool-result самоуверенным «наверное, всё
  ок».
- Не использовать markdown-таблицы в user-facing варианте.
- Не раскрывать токены, env names, provider keys.

## Edge cases

- **Smoke маскируется под обычный текст** (например, переводчик
  пишет «сделай smoke test перевода»). Если явного признака нет —
  уточнить один раз.
- **Smoke задевает plugin, который не установлен.** Сообщить
  честно: «тул `prante_xxx` не зарегистрирован в профиле», не
  пытаться вызвать руками.
- **Smoke в групповом чате, а не в DM.** Не загружать `MEMORY.md`.
  Не считать групповой контекст основной персональной сессией.
- **Smoke запрашивает файл (PDF/XLSX).** Доставка только через
  native attachment rail. Если rail не сработал — файл не доставлен,
  даже если он лежит в workspace.
- **Smoke требует изменить `BOOTSTRAP.md` / удалить его.** Это
  запрещено в smoke. Только онбординг переводчика может удалить
  `BOOTSTRAP.md` после подтверждения.
