# prante-glossary-memory

Skills про **memory approval loop**. Учит модель правильно отличать
одноразовые указания от устойчивых переводческих решений, корректно
формировать кандидатов в `prante_save_memory_candidate` и **никогда**
не повышать статус `candidate` → `user_approved` → `active` без явного
подтверждения переводчика.

## Когда активировать

Активируется, когда переводчик:

- явно говорит «сохрани», «запомни», «одобряю», «в глоссарий»,
  «сделай правилом»;
- присылает пару source/target и явно просит «это в глоссарий»;
- соглашается на ранее предложенного кандидата («да, сохрани
  термин», «правило для проекта X — ок»);
- явно отклоняет кандидата («нет, не сохраняй»).

Не активируется, если:

- переводчик просто обсуждает перевод и не выражает намерения
  запомнить;
- сообщение — operator smoke (см. `prante-operator-smoke`).

## Принципы

1. **`candidate` — это не запись в активную память.** Плагинная БД
   хранит кандидатов со статусом `candidate` всегда, когда плагин
   сам что-то предлагает. Активный статус — только после явного
   подтверждения.
2. **Evidence обязателен.** Каждый кандидат несёт `evidence` (id
   сегментов, support_count, scope, confidence) — без этого
   `prante_save_memory_candidate` отвергает запись.
3. **Конфликт виден.** Новый кандидат vs существующее правило →
   показываем оба, даём переводчику решить, потом сохраняем.
4. **Scope явно выбирается.** `global` / `client` / `project` /
   `genre` / `language_pair`. По умолчанию — `project`, если
   переводчик работает в проекте. Не выдумывай глобальных правил.
5. **Operator smoke → не память.** Если сообщение явно
   операторское, ничего сюда не пишем.

## Шаги

1. **Классифицируй намерение.**
   - одноразовая инструкция («в этом письме переведи X как Y»)
     → не активируем skill, действуем в рамках
     `prante-translation-pass`;
   - durable правило → активируем skill, идём по шагам ниже.

2. **Определи тип кандидата.**
   - `glossary_term` — source term → preferred target, опционально
     forbidden variants и context;
   - `tm_unit` — source segment ↔ target segment, опционально
     статус одобрения;
   - `rule` — style / terminology / formatting / prompt, текст +
     machine_readable_json;
   - `post_edit_pattern` — `pattern_type` + `source_pattern` +
     `draft_pattern` + `final_pattern` + `support_count`.

3. **Сформулируй кандидата на человеческом языке.**
   - что именно сохраняем (source → target, текст правила, паттерн
     правки);
   - scope (глобально / проект X / жанр Y);
   - evidence (откуда взято: N сегментов, support_count, ссылки на
     сегменты);
   - статус по умолчанию — `candidate`.

4. **Проверь конфликты.** Вызови плагин (или plugin DB read-only)
   на наличие:
   - `forbidden_variants` того же source term;
   - активного правила с тем же scope, противоречащего новому;
   - TM-юнита с тем же source и другим target.

   Если конфликт есть — **покажи оба**, не сохраняй молча.

5. **Получи явное подтверждение.** Переводчик должен явно сказать
   «да, сохрани» / «правило для проекта X — ок» / «одобряю».
   - «ага», «ок» после показа кандидата считаем подтверждением
     текущего кандидата в текущем scope.
   - Переводчик может попросить изменить scope, evidence или
     формулировку — обновляем кандидата, снова показываем.

6. **Запиши.** Вызови `prante_save_memory_candidate` с
   `approvalStatus`:
   - `candidate` — без явного подтверждения (по умолчанию);
   - `user_approved` — переводчик явно подтвердил сейчас;
   - `client_approved` — переводчик ссылается на подтверждение
     заказчика (требует отдельного подтверждения);
   - `active` — только если переводчик явно сказал «сделай
     активным» **и** правило прошло plugin validation (нет
     конфликтов, есть evidence, scope валиден).

7. **Подтверди пользователю.**
   - что именно сохранили;
   - scope и статус;
   - evidence (кратко);
   - если конфликт — как разрешили;
   - если есть связанное действие («теперь `prante_glossary_lookup`
     будет возвращать этот термин как preferred») — упомяни.

8. **Обнови `MEMORY.md` / `USER.md` при необходимости.**
   - глобальные правила со статусом `user_approved` / `active` →
     запись в `MEMORY.md` (только в основной персональной сессии,
     и только если переводчик явно одобрил долгосрочное хранение);
   - изменения профиля (новый домен, новая пара, смена стиля) →
     обновление `USER.md` с подтверждения.

## Чего НЕ делать

- Не сохранять ничего в активную память без явного «сохрани» /
  «запомни» / «одобряю».
- Не использовать markdown-таблицы в Telegram.
- Не раскрывать внутренние пути, токены, provider names.
- Не повышать `candidate` до `active` за один шаг — между ними
  всегда стоит явное подтверждение и plugin validation.
- Не сохранять operator smoke как факт о переводчике.
- Не сохранять «правило», если у него нет evidence.

## Конфликт-сценарии

- **Новый preferred vs старый preferred для того же source term:**
  показываем оба, спрашиваем, какой оставить. Старый можно
  перевести в `deprecated` или `conflict`.
- **Новое project rule vs глобальное правило:** `project` > 
  `global` (per `docs/product/adaptive_translation_memory_spec.md`).
  Глобальное правило остаётся в `MEMORY.md`, но в `prompt assembly`
  для проекта X не применяется.
- **TM-юнит и глоссарный термин расходятся:** глоссарий
  приоритетнее для одиночных терминов; TM-юнит может предлагать
  полные сегменты с условием контекста. Показываем оба.
- **Новое правило противоречит `client_approved` правилу:**
  `client_approved` выше; новое идёт в `conflict`, требует
  ручного решения переводчиком.

## Edge cases

- **Переводчик сказал «как обычно» / «как договаривались».** Не
  ищи призрачных правил. Если в `MEMORY.md` ничего нет — спроси
  явно, не выдумывай.
- **Кандидат пришёл из автопайплайна (draft vs final diff).** Это
  всё равно `candidate`, не `user_approved`. Показываем
  переводчику, не активируем.
- **Переводчик редактирует черновик прямо в чате.** Не считаем
  правку автоматическим правилом. После явного «сохрани» —
  идём по шагам.
- **Переводчик даёт bulk-список терминов.** Принимаем как
  `candidate` пакетом, но статус по каждому — `candidate`, пока
  не подтверждён весь пакет или отдельные пункты.
