# ПРАНТЕ — короткий гайд для команды

## Что смотреть

Главный артефакт — сценарий Telegram-бота, а не лендинг.

Локально открыть прототип можно так:

```bash
cd docs/prototypes/final-mvp
python3 -m http.server 8777
# затем открыть http://127.0.0.1:8777
```

В прототипе нужно пройти сценарий: старт, загрузка/вставка текста, ход разбора, отчёт, глоссарий, черновик и подтверждение сохранения правила.

## Как править текст

Основной редакторский контур — Google Sheets. Команда правит таблицу, а прототип подтягивает свежие тексты и показывает preview в:

```text
docs/prototypes/final-mvp/admin/
```

В `/admin/` также можно быстро править тексты прямо в UI. Это удобно для примерки формулировок: preview обновится сразу. Такие правки являются локальным черновиком в браузере; для общей версии нужно экспортировать CSV/JSON и зафиксировать его через Google Sheets или Git.

Если Google Sheets ещё не подключён или временно недоступен, прототип использует fallback JSON:

```text
docs/prototypes/final-mvp/content/prante-content.json
```

Там можно править:

- стартовое сообщение бота;
- команды и кнопки;
- текст пользователя;
- шаги разбора;
- отчёт;
- термины глоссария;
- текст черновика;
- сообщение про сохранение правила;
- поясняющие блоки для сдачи.

Подробный workflow: `docs/prototypes/final-mvp/EDITORIAL_WORKFLOW.md`.

## Что важно не менять без согласования

- Бот должен оставаться главным макетом.
- Сайт/лендинг не должен заменять bot-flow.
- Память сохраняется только после подтверждения пользователя.
- Не добавляйте технические термины в пользовательский интерфейс.
- Не перегружайте текст: проверяющий должен понять сценарий за 30 секунд.

## Как участвовать

1. Посмотреть прототип.
2. Открыть Google Sheets с текстами.
3. Внести правки в колонку `Текст`.
4. Проверить `/admin/`, что preview не показывает ошибок.
5. После согласования разработчик фиксирует snapshot в Git.

Если таблицу нужно открыть локально, используйте файл:

```text
docs/prototypes/final-mvp/content/editor-texts-template.xlsx
```

CSV-файлы нужны в первую очередь для импорта, публикации и автоматической синхронизации.

## Как будут проверяться правки

1. Команда меняет только текстовые поля или явно согласованные UI-части.
2. Проверяется, что сценарий не сломан и текст не противоречит документам проекта.
3. После согласования фиксируется версия для сдачи.
