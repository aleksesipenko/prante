# PRANTE — Project 2 / Task 3 MVP spec

## Что мы делаем

Для задания 3 мы делаем **MVP-прототип ПРАНТЕ** как Telegram-first пользовательский сценарий, который можно показать, кликать и потом тестировать на респондентах.

Формат:
- clickable HTML mockup;
- supporting markdown spec;
- короткий handoff для Алсу/команды.

## Что именно входит в MVP

### Screen 1 — Start / value proposition
Показываем:
- что такое ПРАНТЕ;
- для кого он;
- какую боль снимает;
- CTA: `Вставить текст` / `Загрузить файл`.

### Screen 2 — Input
Показываем:
- ввод текста;
- загрузку PDF/DOCX;
- выбор языка / режима анализа;
- кнопку `Запустить анализ`.

### Screen 3 — Pre-translation analysis
Показываем:
- повторы;
- ключевые термины;
- жанр/стиль;
- риски читабельности;
- краткий отчет по сложности текста.

### Screen 4 — Glossary suggestions
Показываем:
- найденные термины;
- suggested translations;
- действия: `Запомнить`, `Игнорировать`, `Изменить`.

### Screen 5 — Draft translation
Показываем:
- черновой перевод с учетом глоссария;
- пометки по спорным местам;
- CTA: `Отредактировать`.

### Screen 6 — Post-edit / save learning
Показываем:
- что пользователь внес правки;
- бот предлагает сохранить:
  - термин,
  - стиль,
  - правило проекта.

### Screen 7 — Result / memory effect
Показываем:
- что сохранено в памяти;
- как это поможет в следующем переводе;
- итоговую ценность MVP.

## Что проверяющий должен понять за 30 секунд

1. Это продукт для письменного переводчика.
2. Он ускоряет предпереводческую подготовку.
3. Он помогает с терминологией.
4. Он дает черновик перевода.
5. Он учится на правках пользователя.

## Что не входит в MVP

Не делаем сейчас:
- полноценный backend;
- реальную LLM-интеграцию;
- сложную админку;
- большой веб-кабинет;
- enterprise CAT-функции.

## Deliverables

### 1. HTML mockup
Файл с кликабельным сценарием MVP.

### 2. Spec
Этот документ — screen-by-screen расшифровка.

### 3. Team handoff note
Короткое объяснение:
- что именно сделано;
- почему это уже MVP;
- как это связано с исследованием.

## Что отдаем Алсу

Минимум:
- ссылку/файл с прототипом;
- краткое описание MVP;
- 3–5 bullets, как research повлиял на решение.
